# Matriz de trazabilidad del MVP del TFG

Fecha de referencia: 2026-09-02.

Este documento cruza los compromisos del trabajo final, el backlog vigente y el comportamiento comprobable del repositorio. Se mantiene como documentación local del proyecto; no reemplaza los contratos, las migraciones ni las pruebas.

## Criterio de lectura

Los estados tienen este significado:

- `hecho`: existe comportamiento persistente en API real y una prueba automatizada o una comprobación reproducible.
- `parcial`: existe una parte del flujo, pero falta una regla, una superficie, una integración o evidencia necesaria.
- `pendiente P0`: bloquea la demostración mínima comprometida.
- `pendiente P1`: mejora la calidad, operación o evidencia, pero no bloquea el caso vertical si se deja declarado.
- `fuera de alcance`: pertenece a una evolución posterior y no se presenta como disponible.

Una prueba de frontend con MSW demuestra la interfaz aislada, no la persistencia, autorización, latencia ni la comunicación real con PostgreSQL o Socket.IO. Las capturas y comprobaciones manuales se agregan cuando se ejecutan con `PUBLIC_API_USE_MOCKS=false`.

| Estados editoriales         | Evita presentar pendiente, corrección o rechazo como disponible.       | Backend + producto   | La base, la API de propietario y los filtros públicos conservan y respetan el estado; la revisión avanzada no se presenta como disponible. |
| Zona de referencia          | Protege domicilio y mantiene utilidad territorial.                     | Producto + backend   | El mapa y los detalles públicos muestran barrio/ciudad o aproximación, nunca calle, altura ni coordenadas exactas.                         |
| Recordatorio                | Cierra el acuerdo sin depender de email o push.                        | Backend + frontend   | Un acuerdo confirmado genera como máximo un aviso in-app por versión y destinatario, respetando cambios y cancelación.                     |
| Cierre del encuentro        | Permite medir el resultado sin publicar datos personales.              | Producto + backend   | Cada participante puede registrar completado/no completado y el historial conserva la decisión autorizada.                                 |
| Español neutro              | Mantiene consistencia de la interfaz y de los errores.                 | Frontend + producto  | Las rutas principales y todas las claves nuevas se revisan en español neutro.                                                              |
| Reportes mínimos            | Ofrece recepción y trazabilidad sin fingir moderación avanzada.        | Producto + operación | Cada reporte autenticado tiene categoría, motivo, fecha, estado, canal y plazo documentados.                                               |
| Evidencia                   | Hace auditable el cierre del TFG.                                      | Operación + producto | Cada P0 enlaza una prueba o captura reproducible, entorno, fecha y límite conocido.                                                        |

## Estado de cierre

La matriz queda abierta mientras haya filas `pendiente P0`, `parcial` con impacto en el recorrido principal o evidencia crítica ausente. Las capacidades de recomendación automática, email/push productivo, MFA, moderación avanzada, reputación, almacenamiento de objetos y analítica avanzada se mantienen fuera del MVP y no se contarán como trabajo pendiente de cierre.
