# Matriz de reconexión entre frontend y backend

Fecha de auditoría: 2026-08-31. Esta matriz es la línea de trabajo del cambio OpenSpec `reconnect-backend-to-prototype-frontend`; complementa [`prototype-mock-contract.md`](prototype-mock-contract.md). Los valores de `prototypeCatalog` y `PrototypeContext` prueban composición visual, no persistencia.

## Criterio de decisión

- **Reconectar**: el contrato existente aporta la lectura o mutación necesaria; el frontend necesita un adaptador de modelo de vista.
- **Adaptación compatible**: la capacidad y datos base existen, pero falta un agregado o campo de presentación. Todo cambio backend será aditivo y guiado por el modelo de vista frontend.
- **Diferir**: no hay contrato persistido suficiente. En modo API real la región muestra un estado limitado diseñado, nunca contenido demo presentado como real.

Los endpoints se montan bajo `/api`; las filas autenticadas usan cookie de sesión. Los errores públicos conservan sus claves i18n. La evidencia es estática (rutas, servicios y clientes existentes); cada fila completada requiere además pruebas HTTP/Socket.IO y navegador.

## Eventos y seguridad

| Evento o mutación            | Persistencia/autorización auditada                            | Uso objetivo                                            |
| ---------------------------- | ------------------------------------------------------------- | ------------------------------------------------------- |
| `conversation:join`          | valida participante, une sala y recupera mensajes tras cursor | Sincronizar conversación tras reconexión.               |
| `conversation:message`       | persiste con `clientKey`, notifica y emite a sala             | Reconciliar mensaje, preview y no leídos.               |
| `conversation:read`          | valida participante y persiste secuencia                      | Actualizar indicador sin estado ficticio.               |
| `agreement:updated`          | se emite tras commit a la sala                                | Refrescar tarjeta de propuesta.                         |
| Rutas de mensajes/acuerdos   | sesión y controles de participante/estado                     | Mantener i18n, cursores, deduplicación y prohibiciones. |
| Perfil, publicación y rincón | sesión; edición de propietario                                | No habilitar controles que omitan autorización.         |

## Diferidos para una OpenSpec posterior

1. Agregado personalizado de Inicio: recomendaciones y KPIs diarios/personales.
2. Analitica social avanzada: media, libro enlazado, reacciones/comentarios en tiempo real, eventos y moderacion.
3. Analítica: series, comparativos, rankings, mapa de actividad y exportación.
4. Perfil lector: métricas, objetivo, racha, logros y relaciones.
5. Mapa enriquecido: clusters, heatmap, actividad no derivable y política explícita de ubicación aproximada.
6. Ayuda gestionable: FAQ/categorías/búsqueda y chat o tickets de soporte.
7. Mensajes con adjuntos tipados cuando una card no pueda derivarse de un acuerdo.

Toda capacidad diferida requerirá entidades/relaciones, lecturas paginadas, mutaciones, autorización, errores i18n, vacío, política de medios/privacidad, eventos si aplican y pruebas de persistencia. Hasta entonces, API real conserva la región visual y muestra disponibilidad limitada explícita.
